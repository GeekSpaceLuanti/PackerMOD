# 操作テスト結果（2026-11-04）

Minetest GameでPackを保存できなかった原因は、LuantiのゲームID `minetest` をフォルダー名と扱い、実際の `minetest_game` を発見できなかったことです。ゲームIDからのパス決め打ちをやめ、エンジンが返す実パスをPack保存とワールド作成の両方で使うよう修正しました。

## 修正した不具合

| 条件 | 修正後 |
|---|---|
| インストール済みゲームのIDとフォルダー名が異なる／共有パスにある | エンジンのゲーム一覧から実パスを解決する |
| 日本語だけのワールド名 | UTF-8名を保持する。改行等の制御文字を拒否し、Windows予約名は安全な名前に変換する |
| MODのZIPに親フォルダーがある | 実MODルートを見つけて配置する。不正なZIPは保存先へ公開しない |
| ポータブル版のパスに `bin/..` が含まれる | ZIP展開に渡すパスを正規化する |
| ハッシュ未指定のURL由来MODが複数ある | URLごとにキャッシュを分離する |
| 新規ワールドで設定保存・MOD導入・Pack状態保存に失敗する | 作成途中のワールドを除去して同名で再試行できるようにする。除去失敗は報告する |
| ImportしたゲームID・packageの型が不正 | Lua例外を起こさず検証エラーを返す |
| サーバーポートが0・負数・小数・65536以上 | 登録時に拒否する |

`operations_test` の直積:

- ゲーム配置3種類: `matrix_game`をID `matrix`で使用、通常ID `plain`、版別ID `pm_downloaded_r42`。
- MOD4種類: なし、同梱、ContentDBキャッシュ内の親フォルダー付きZIP、URLキャッシュ内のルート直下ZIP。
- ワールド名2種類: 英数字、日本語のみ。
- 各条件で3回起動: 新規、再起動、MOD削除後。ゲーム内でMODのロード状態を照合する。

さらに実ファイルで、YAML／ZIP取り込み、同ID・同名ワールドの拒否、Pack情報の更新、サーバー一覧の追加・削除、ワールド削除、起動用ディレクトリと設定の復元を確認します。全試験のPack・ワールドは隔離データです。

## 確認の限界

任意の操作順序、公開ゲーム／MODの全種類・依存関係、実外部マルチプレイサーバーへの接続、ネットワーク障害の全パターンは網羅していません。72回の起動マトリクスでは最小フィクスチャと既存キャッシュを使い、実通信は別のContentDB試験で確認しています。「全組み合わせでバグなし」という保証ではありません。

Windows実画面の自動取得は承認待ちがタイムアウトしたため未実施です。Windowsのゲーム起動はエンジンログとゲーム内検証MODで確認し、画面は指定のWSL＋Xvfb撮影で確認しました。
